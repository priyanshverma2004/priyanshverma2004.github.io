R-001 AI Interview Coach Flask · Gemini 2.5 Flash 8 routes6 templates 2026

A mock-interview app that adapts to the role, the job description and the candidate's résumé. Gemini writes the questions, scores each answer on communication, technical accuracy and problem solving, and the app turns the session into a report you can revisit.

Role
Solo build — interface, backend, prompts
Stack
Python · Flask · Gemini API · Jinja · Chart.js
Evidence
8 routes, 6 templates, 4 service modules; each report persisted as JSON
Status
Runs locally with a Gemini key; no public demo
  • Kept interview state server-side so a page refresh does not lose the session.
  • Added a mock mode that returns canned questions when no API key is present, so the interface can be reviewed without credentials.
  • Enforced question order and saved every report to disk — the dashboard is a file listing, not a database.

Honest limitation: flat JSON files do not scale and there is no authentication. It is a complete demo, not a multi-user product.

R-002 Email Spam Classifier NLP · scikit-learn 97.1%1,035 held-out emails 2026

A text classifier that separates ham from spam with a bag-of-words representation and Multinomial Naive Bayes. The interesting part was not the model; it was measuring it against a baseline and reporting the class that matters.

Data
5,171 labelled emails — 3,672 ham, 1,499 spam
Split
80 / 20 at random_state 42 — 1,035 emails held out
Baseline
Predict the majority class: 71.7% (742 / 1,035)
Result
97.1% accuracy; spam precision 0.95, recall 0.95, F1 0.95
  • Kept the model deliberately simple, so a later TF-IDF or SVM version has something real to beat.
  • Reported per-class precision and recall, because missing spam and flagging a genuine email have different costs.
  • Noted the dataset's Enron-era vocabulary: this model learned 2001 spam, not 2026 spam.

R-003 Customer Churn Prediction ML · Streamlit 0.868 AUC200 test rows 2026

A churn classifier with a small Streamlit front end: ten customer fields in, churn probability out. I compared a linear baseline with a random forest and selected on ROC-AUC, because the classes are not balanced.

Data
1,000 Telco-format customer records
Models
Logistic regression vs. random forest (200 trees, max depth 10)
Test
200 held-out rows, 20% split
Result
Random forest 0.868 ROC-AUC, 0.79 accuracy; logistic 0.859
  • Wrapped preprocessing and model in one scikit-learn Pipeline, so training and serving cannot drift apart.
  • Chose AUC over accuracy because a model that always predicts “stays” can still look plausible.
  • Kept the caveat visible: 200 test rows means the interval around that AUC is wide.

R-004 Sentiment Analysis NLP · a cautionary tale 100%and that is the problem 2026

A sentiment classifier trained on 1,000 synthetic reviews. Logistic regression and Naive Bayes both scored 100% on the held-out set. That result is the most useful thing in the repository: it says the dataset was too easy, not that the model is finished.

Data
1,000 synthetic positive / negative reviews
Models
Logistic regression and Multinomial Naive Bayes
Result
1.00 accuracy for both on 200 test rows
Read
A suspicious score — likely template overlap between splits
  • Published the result as-is instead of quietly replacing it with a friendlier number.
  • Wrote down the next check: a harder, real review set with neutral examples and negation.
  • Kept the Streamlit demo small so the model can be swapped in one file.
