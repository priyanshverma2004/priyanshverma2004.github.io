AI Interview Coach

A Flask app that turns a job description and a résumé into a realistic mock interview — then writes the feedback report a candidate would otherwise have to imagine.

1. The problem

Interview practice is easy to start and hard to judge. A friend can ask questions, but they cannot consistently score the answer, remember what you missed last time, or tell you the difference between “vague” and “wrong”. Generic question lists do not adapt to the role you are actually applying for.

This project asks a narrower question: can a single Flask app produce a complete practice loop — tailored questions, an evaluation per answer, and a report worth re-reading — without a database, a frontend framework, or a team?

The constraint that shaped everything: it had to be reviewable by someone who does not have a Gemini API key. That one requirement produced the mock mode, the seed data, and most of the architecture below.

2. What it does

The candidate chooses a role, pastes a job description and résumé (both optional), picks a difficulty and a question count. The app generates a fresh set of questions, walks through them one at a time, evaluates each answer, and finishes with a scored report.

01 · SETUPRole, JD, résumé, difficulty, count
→
02 · GENERATEGemini returns a JSON array of questions
→
03 · ANSWEROne question per page, answers saved
→
04 · EVALUATEScore, strengths, gaps, model answer
→
05 · REPORTOverall score, three categories, next steps

Each answer receives a 0–10 score, a correctness analysis, strengths, weaknesses, explicit errors, suggestions, and a model answer. The final pass compresses the whole transcript into an overall score out of 100, three category scores, top skills and recommendations.

3. How it is built

There is no build step and no client-side framework. Flask renders six Jinja templates; a small amount of JavaScript draws the dashboard charts. The interesting separation is on the server: routes do HTTP, the engine owns session state, the service owns prompts, and the report layer owns aggregation.

app.py8 routes · session cookie
→
interview_engineState, ordering, completion
→
gemini_servicePrompts + JSON mode + fallbacks
→
report_generatorAverages, trends, skills

Questions are requested with response_mime_type: application/json, so the model returns a JSON array instead of a prose list wrapped in markdown. The response is parsed and validated as a non-empty list; if anything fails — a timeout, a malformed object, an exhausted quota — the service logs the error and falls back to a canned question bank rather than breaking the interview.

Active sessions are stored as active_<uuid>.json; completed reports as report_<uuid>.json. Only the session ID lives in the Flask cookie. The dashboard lists the report folder, aggregates averages with Python, and exposes the same numbers at /api/dashboard-data for Chart.js.

4. Decisions and trade-offs

Files instead of a database

A JSON file per report means zero setup, an obvious audit trail, and a demo that runs with python app.py. The cost is real: no concurrent writes, no user scoping, no query layer, and a dashboard that reads every file on every request. For one user this is a feature; for ten it is a bug.

A strict question order

The route checks the requested index against the server's current index and redirects if they disagree. This prevents skipping ahead or resubmitting an answer, and keeps the state machine understandable. It also means a candidate cannot go back and revise an earlier answer — a deliberate trade-off I would revisit before calling this a product.

Mock mode as a first-class path

When no key is configured, the service serves a curated question bank and deterministic evaluations. This was not an afterthought: it is why the interface can be reviewed in a browser without secrets, and it doubles as a fallback when the API is unavailable.

Structured output, with a fallback

Every prompt asks for raw JSON, and the call sets the response MIME type. Even so, parsing is wrapped: a malformed response logs and falls back. Trusting a model to be valid JSON is not a strategy; validating it is.

The repository includes the Flask app, the six templates, the static assets, and sample report JSON. There is no public deployment: the app needs a Gemini key, and I would rather link a repository that runs than a demo that does not. The README documents the two commands needed to start it.

What this does not prove: that the questions are good. There is no evaluation set of interview questions, no inter-rater comparison, and no evidence that a higher score predicts a better interview. Those are open questions, not claims.

6. What I would fix next

  • Authentication and real storage. Move sessions and reports to SQLite or Postgres, scope them to a user, and delete the flat-file layer.
  • Production hygiene. Turn off debug=True, remove the default secret-key fallback, and move rate limiting in front of the Gemini calls.
  • Cost and latency visibility. Log tokens and response time per request; a mock-interview app that quietly burns quota is a bad demo.
  • Let candidates revisit an answer. Keep the order, but allow a review step before final submission.
  • Export. A printable PDF report is the obvious next feature; the data is already structured for it.
  • Voice. The original motivation. Speech-to-text would make practice feel like an interview rather than a form.
